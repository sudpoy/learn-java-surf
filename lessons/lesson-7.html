Classes & Objects

This is the big one — the heart of Java. So far your programs have been lists of instructions. Now you'll learn to build your own things: a Dog, a player, a bank account. A class is a blueprint, and an object is a real thing built from that blueprint. This idea is called Object-Oriented Programming, and it's how almost all real Java is written.

Lecture: ~40 min
Exercise: ~15 min
Topics: class · object · fields · new · constructor · this · static · encapsulation
Part 1 — A Blueprint and the Things Built From It

Think about a cookie cutter. The cutter itself isn't a cookie — it's the shape that decides what every cookie will look like. Press it into dough and you get an actual cookie. Press it again and you get another, and another. One cutter, many cookies.

In Java, a class is the cookie cutter, and an object is each cookie you make with it. The class describes what every object will be like — what information it holds and what it can do. An object is one real, individual thing built from that description.

Class (the blueprint)Object (a real thing built from it)
Written onceYou can build as many as you want
Describes the shape: "a Dog has a name and an age"Holds actual values: name = "Rex", age = 3
Doesn't do anything on its ownExists in memory; you can use it

Here's our first class — a Dog blueprint — and one object built from it. The Dog class lists what every dog has; main builds a single dog and fills in its details:

class Dog {
    String name;     // every Dog will have a name
    String breed;    // ...a breed
    int age;         // ...and an age
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();          // build ONE dog from the blueprint
        d.name = "Rex";             // fill in this dog's details
        d.breed = "Labrador";
        d.age = 3;
        System.out.println(d.name + " is a " + d.age + "-year-old " + d.breed + ".");
    }
}
💡 Two classes in one file

Notice there are two classes here: Dog (our blueprint) and Main (where the program starts). That's totally normal. The program always begins in main, just like before — but now main can build and use Dog objects. The dot (d.name) means "reach into object d and get its name."

Part 2 — Fields & Building Objects with new

The variables inside a class — like name, breed, and age — are called fields (also "instance variables"). They're the information each object carries. The keyword new is what actually builds an object: it's the construction crew that takes the blueprint and makes a real thing in memory.

What's in a brand-new object before you fill it in? Java gives every field a default value: numbers start at 0, and object types like String start at null (meaning "nothing here yet").

class Dog {
    String name;
    int age;
}

public class Main {
    public static void main(String[] args) {
        Dog a = new Dog();                       // a fresh, empty dog
        System.out.println("Fresh name: " + a.name);   // null
        System.out.println("Fresh age:  " + a.age);    // 0

        a.name = "Buddy";                        // now give it real values
        a.age = 5;
        System.out.println(a.name + " is now " + a.age + ".");
    }
}
⚠️ The variable is not the object

Dog a = new Dog(); has two halves. new Dog() builds the actual object; Dog a is just a label pointing at it (called a reference). Filling in fields one by one works, but it's easy to forget one. The next part shows a much cleaner way to build a fully set-up object in a single step.

Part 3 — Constructors: Setting Up a New Object

Setting every field by hand is tedious. A constructor fixes that: it's a special block that runs automatically the moment an object is built with new. Give it parameters, and you can create a fully-prepared object in one line. A constructor has the same name as the class and no return type.

class Dog {
    String name;
    int age;

    Dog(String name, int age) {   // CONSTRUCTOR — same name as the class
        this.name = name;         // store the values into this object's fields
        this.age = age;
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog("Rex", 3);   // build AND set up, all in one line
        System.out.println(d.name + " is " + d.age + " years old.");
    }
}
💡 What is this?

Inside the constructor, the parameter is also called name — so how does Java know which is which? this.name means "the field belonging to this particular object," while plain name is the parameter that was passed in. So this.name = name; reads as "set this object's name field to the value I was handed." You'll see this a lot — it always means "the object I'm working on right now."

Part 4 — Giving Objects Behavior (Methods)

Objects don't just hold data — they can do things. A method written inside a class is an instance method: it belongs to each object and can use that object's own fields directly. Let's teach our Dog to bark and to have a birthday:

class Dog {
    String name;
    int age;

    Dog(String name, int age) {
        this.name = name;
        this.age = age;
    }

    void bark() {
        System.out.println(name + " says: Woof!");   // uses THIS dog's name
    }

    void haveBirthday() {
        age = age + 1;                                // changes THIS dog's age
        System.out.println(name + " is now " + age + ".");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog("Rex", 3);
        d.bark();
        d.haveBirthday();
        d.haveBirthday();
    }
}
⚠️ Methods act on their own object

When you call d.bark(), the method automatically uses d's fields — its name, its age. If you built a second dog and called other.bark(), it would use that dog's name instead. The same method, written once, behaves differently for each object because each object has its own data.

Part 5 — Instance vs. static (Why main Is static)

Back in Lesson 5, every helper method was static, and main is static too. Now you can finally see what that word means. static means "belongs to the class itself, not to any one object" — so it can run without building an object first. That's exactly why main is static: Java needs to start your program before any objects exist.

Instance (no static)static
Belongs toEach individual objectThe whole class
CopiesOne per object (each dog its own)Just one, shared by all
Called onAn object: d.bark()The class: Dog.dogCount

A static field is shared by every object of the class — perfect for something like "how many dogs have been created in total," which isn't about any single dog:

class Dog {
    static int dogCount = 0;   // ONE counter, shared by all dogs
    String name;               // each dog gets its OWN name

    Dog(String name) {
        this.name = name;
        dogCount++;            // every time a dog is born, bump the shared count
    }
}

public class Main {
    public static void main(String[] args) {
        Dog a = new Dog("Rex");
        Dog b = new Dog("Luna");
        Dog c = new Dog("Max");
        System.out.println("Names: " + a.name + ", " + b.name + ", " + c.name);
        System.out.println("Dogs created: " + Dog.dogCount);   // on the CLASS, not an object
    }
}
💡 The rule of thumb

If something belongs to one specific object (this dog's name, this account's balance), it's an instance field or method — no static. If it belongs to the idea of the class as a whole (a total count, or a helper like the math methods from Lesson 5), it's static. Most of what you write on your own classes will be instance members.

Part 6 — Protecting Your Data (a Gentle Intro to Encapsulation)

Imagine a bank where anyone could reach into the vault and change the numbers directly. Disaster! Real banks make you go through a slot — a deposit window, an ATM — that checks every request. In Java, hiding a field with private and only allowing access through methods is called encapsulation. It keeps an object's data safe and valid.

Mark a field private and code outside the class can't touch it directly. Instead you offer methods: a getter to read the value, and a method like deposit (a kind of setter) that guards changes:

class BankAccount {
    private double balance;          // hidden — no outside code can change it directly

    public void deposit(double amount) {
        if (amount > 0) {            // the guard: only allow sensible deposits
            balance = balance + amount;
        }
    }

    public double getBalance() {     // a "getter" — lets others READ the balance
        return balance;
    }
}

public class Main {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount();
        acc.deposit(100);
        acc.deposit(50);
        acc.deposit(-9999);          // rejected by the guard — balance is protected
        System.out.println("Balance: " + acc.getBalance());
    }
}
⚠️ private really means private

Because balance is private, a line like acc.balance = 999999; written in main wouldn't even compile — Java blocks it. That's the point: the only way to change the balance is through deposit, which checks the amount first. The object stays in a valid state no matter what. You'll go much deeper on this in Lesson 8.

Part 7 — Many Objects, Each With Its Own State

Here's the real payoff. From one class you can build as many objects as you like, and each one keeps its own separate data. Changing one object never touches another — just like decorating one cookie doesn't change the others on the tray.

class Dog {
    String name;
    int age;

    Dog(String name, int age) {
        this.name = name;
        this.age = age;
    }

    void describe() {
        System.out.println(name + " is " + age + " years old.");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog rex  = new Dog("Rex", 3);
        Dog luna = new Dog("Luna", 7);

        rex.describe();
        luna.describe();

        rex.age = 4;             // changes ONLY Rex
        System.out.println("--- after Rex's birthday ---");
        rex.describe();
        luna.describe();         // Luna is untouched
    }
}
💡 Two labels, two separate dogs

rex and luna point at two completely separate objects, each with its own name and age in memory. That's why bumping rex.age leaves luna.age alone. One blueprint, many independent objects — that's the whole power of classes.

⌨️ Coding Challenge ⏱ ~15 min

Task 1 — A Cat class
Write a Cat class with a String name field, a constructor Cat(String name), and a method void meow() that prints name + " says: Meow!". In main, build a cat named "Whiskers" and call meow().

Hint: keep Cat as a separate class and leave public class Main for main.

Structure it like the Dog example: class Cat { String name; Cat(String name){ this.name = name; } void meow(){ System.out.println(name + " says: Meow!"); } } then in main: Cat c = new Cat("Whiskers"); c.meow();

Task 2 — A Rectangle that knows its area
Write a Rectangle class with int width and int height fields, a constructor that sets both, and a method int area() that returns width * height. Build a 4×6 rectangle and print its area (you should get 24).

The constructor takes two parameters: Rectangle(int width, int height){ this.width = width; this.height = height; }. The method returns a value: int area(){ return width * height; }. Then Rectangle r = new Rectangle(4, 6); System.out.println(r.area());

Task 3 — Two Players, two scores
Write a Player class with an int score (starts at 0) and a method void addPoints(int p) that adds p to the score. Create two players, add different points to each, and print both scores to prove they're independent.

A field can start at 0 by default, so you may not even need a constructor. class Player { int score; void addPoints(int p){ score = score + p; } }. Make two: Player p1 = new Player(); Player p2 = new Player(); then p1.addPoints(10); p2.addPoints(3); and print p1.score and p2.score — they hold separate values.
