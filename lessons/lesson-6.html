Recursion

A method that calls itself. It sounds like magic (or a trick question), but recursion is just a method solving a big problem by handing a slightly smaller version of it to a copy of itself — until the problem gets so small the answer is obvious. Learn the base case, the recursive case, and how the call stack makes it all work.

Lecture: ~40 min
Exercise: ~15 min
Topics: base case · recursive case · call stack · factorial · Fibonacci · stack overflow
Part 1 — What Is Recursion?

Picture a set of Russian nesting dolls. You open the big doll and find a smaller doll inside. You open that one and find an even smaller doll. You keep going until you reach the tiniest doll, which doesn't open — it's solid. Recursion is exactly this idea in code: a method that calls itself on a smaller piece of the problem, again and again, until it reaches a piece so small there's nothing left to break down.

In Lesson 5 you saw one method call another method. Recursion is just a method calling itself. Here is the shortest possible example — a countdown:

public class Main {

    static void countdown(int n) {
        if (n == 0) {                       // the tiniest doll — stop here
            System.out.println("Liftoff!");
            return;
        }
        System.out.println(n);
        countdown(n - 1);                   // call MYSELF with a smaller number
    }

    public static void main(String[] args) {
        countdown(3);
    }
}
💡 It's not as strange as it looks

When countdown(3) runs countdown(2), that's just a normal method call — Java doesn't care that the method happens to have the same name. It runs a fresh copy with n set to 2. Each copy has its own n, exactly like the local variables you met in Lesson 5.

Part 2 — The Two Essential Parts

Every correct recursive method has exactly two parts. Miss either one and it breaks. Learn these two words and you understand 90% of recursion:

PartWhat it isIn the countdown
Base caseThe simplest version, where you know the answer immediately and stop — no more callsif (n == 0) → print "Liftoff!" and return
Recursive caseYou do a little work, then call the method again on a smaller input, moving toward the base casecountdown(n - 1)

The golden rule: every recursive call must move closer to the base case. The countdown subtracts 1 each time, so 3 → 2 → 1 → 0, and at 0 it stops. If it ever moved away from the base case, it would never stop.

Same Shape, Different Job

Here's a method that adds up 1 + 2 + 3 + ... + n. Look for the same two parts: a base case that stops, and a recursive case that shrinks the problem.

public class Main {

    static int sumTo(int n) {
        if (n == 1) {              // BASE CASE: sum of just 1 is 1
            return 1;
        }
        return n + sumTo(n - 1);   // RECURSIVE CASE: n plus the sum of everything below it
    }

    public static void main(String[] args) {
        System.out.println("Sum 1..5 = " + sumTo(5));   // 1+2+3+4+5
        System.out.println("Sum 1..10 = " + sumTo(10));
    }
}
💡 Trust the smaller call

The trick to writing recursion: assume sumTo(n - 1) already works and gives the right answer for the smaller problem. Then you only have to figure out how to combine it with n. Here, the sum of 1..n is just n added onto the sum of 1..(n-1). Don't try to trace every call in your head — trust the smaller call to do its job.

Part 3 — A Traced Walkthrough: factorial

The classic recursion example is factorial. The factorial of 4 (written 4!) means 4 × 3 × 2 × 1 = 24. Notice that 4! is just 4 × 3! — the problem contains a smaller copy of itself. Perfect for recursion:

public class Main {

    static int factorial(int n) {
        if (n == 0) {                  // BASE CASE: 0! is defined as 1
            return 1;
        }
        return n * factorial(n - 1);   // RECURSIVE CASE: n times (n-1)!
    }

    public static void main(String[] args) {
        System.out.println("4! = " + factorial(4));
    }
}

Let's trace factorial(4) by hand. Recursion happens in two phases. First the calls wind up — each one pauses, waiting on a smaller call — until the base case is hit. Then they unwind, each returning its answer to the one that was waiting:

WINDING UP (each call waits on a smaller one): factorial(4) = 4 * factorial(3) ← paused, needs factorial(3) factorial(3) = 3 * factorial(2) ← paused, needs factorial(2) factorial(2) = 2 * factorial(1) ← paused, needs factorial(1) factorial(1) = 1 * factorial(0) ← paused, needs factorial(0) factorial(0) = 1 ← BASE CASE! answer is known, stop UNWINDING (each waiting call now finishes): factorial(1) = 1 * 1 = 1 factorial(2) = 2 * 1 = 2 factorial(3) = 3 * 2 = 6 factorial(4) = 4 * 6 = 24 ← final answer
⚠️ The answer is built on the way back

A common surprise: almost no multiplication happens on the way down. The calls just stack up, each one stuck waiting. The real work — the multiplying — happens on the way back up, once the base case finally hands back a concrete number to multiply with. Down to find the base case, back up to build the answer.

Part 4 — The Call Stack

How does Java remember all those paused calls? With the call stack — think of a stack of plates. Every time a method is called, Java puts a new plate on top with that call's own variables. When a method returns, its plate is taken off the top, and Java goes back to the plate underneath — exactly where it left off.

"Stack" means last on, first off, like real plates: the last plate you put down is the first one you pick up. During factorial(4), the stack grows to five plates tall, then shrinks back down one plate at a time as each call returns:

Stack at its TALLEST (just as factorial(0) runs): ┌─────────────────┐ ← top plate (added last, removed first) │ factorial(0) │ ├─────────────────┤ │ factorial(1) │ waiting for factorial(0) ├─────────────────┤ │ factorial(2) │ waiting for factorial(1) ├─────────────────┤ │ factorial(3) │ waiting for factorial(2) ├─────────────────┤ │ factorial(4) │ waiting for factorial(3) ├─────────────────┤ │ main │ waiting for factorial(4) └─────────────────┘ ← bottom plate (where it all started)
💡 Each plate has its own variables

Every plate keeps its own copy of n. The plate for factorial(2) has n = 2; the one for factorial(3) has n = 3 — at the very same time. They never get mixed up, which is the whole reason recursion works. This is just local scope (Lesson 5) doing its job, one plate per call.

Part 5 — More Classic Patterns

Once you spot the shape — base case + smaller call — you can write all sorts of recursive methods. Here's power: raising a number to a whole exponent. Note that base⁰ = 1 for any base, which gives us a clean base case.

public class Main {

    // Computes base raised to the power exp, e.g. power(2, 5) = 32
    static int power(int base, int exp) {
        if (exp == 0) {                     // BASE CASE: anything to the 0 is 1
            return 1;
        }
        return base * power(base, exp - 1); // RECURSIVE CASE: one fewer multiply
    }

    public static void main(String[] args) {
        System.out.println("2^5 = " + power(2, 5));
        System.out.println("3^4 = " + power(3, 4));
        System.out.println("5^0 = " + power(5, 0));
    }
}

Recursion also shines on problems that are naturally "made of themselves." Checking whether a word is a palindrome (reads the same forwards and backwards, like "racecar") is one: a word is a palindrome if its first and last letters match and the bit in the middle is also a palindrome.

public class Main {

    static boolean isPalindrome(String s) {
        if (s.length() <= 1) {              // BASE CASE: empty or single letter
            return true;                    // always reads the same both ways
        }
        char first = s.charAt(0);
        char last  = s.charAt(s.length() - 1);
        if (first != last) {
            return false;                   // ends don't match — not a palindrome
        }
        // chop off both ends, check the smaller middle
        return isPalindrome(s.substring(1, s.length() - 1));
    }

    public static void main(String[] args) {
        System.out.println("racecar -> " + isPalindrome("racecar"));
        System.out.println("hello   -> " + isPalindrome("hello"));
        System.out.println("noon    -> " + isPalindrome("noon"));
    }
}
Part 6 — Fibonacci: When a Call Splits in Two

The Fibonacci sequence starts 0, 1, 1, 2, 3, 5, 8, 13, ... — each number is the sum of the two before it. Because each answer depends on two smaller answers, the recursive case makes two calls. This needs two base cases too:

public class Main {

    static int fib(int n) {
        if (n == 0) return 0;            // BASE CASE 1
        if (n == 1) return 1;            // BASE CASE 2
        return fib(n - 1) + fib(n - 2);  // RECURSIVE CASE: two calls, added
    }

    public static void main(String[] args) {
        for (int i = 0; i <= 10; i++) {
            System.out.print(fib(i) + " ");
        }
        System.out.println();
    }
}
⚠️ Beautiful, but secretly slow

This fib is lovely to read but does a huge amount of repeated work — fib(5) ends up computing fib(2) three separate times! For small n it's fine, but try fib(45) and you'll wait a long time. It's a perfect reminder that "recursion works" doesn't always mean "recursion is the fast choice."

Part 7 — Recursion vs. Loops

Here's a secret: anything you can do with recursion, you can also do with a loop, and vice-versa. They're two ways to repeat work. So which should you reach for? Compare the same countdown both ways:

Loop versionRecursive version
for (int i = n; i > 0; i--)
  print(i);		 if (n == 0) return;
print(n);
countdown(n - 1);

For a plain countdown, the loop is simpler — fewer moving parts and no stack piling up. Reach for a loop when you're just repeating a fixed number of times or marching through an array.

Recursion wins when the problem is naturally nested or branching — things that contain smaller copies of themselves: exploring folders inside folders, navigating a family tree, or splitting a list in half again and again. For those, a recursive solution is often far shorter and clearer than the loop equivalent.

💡 Rule of thumb

Use a loop for simple, flat repetition (count, sum an array, repeat N times). Use recursion when the problem breaks into smaller versions of the same problem. If you can describe the answer in terms of "the answer to a smaller version," recursion will feel natural.

Part 8 — The #1 Danger: A Missing Base Case

Recursion has one famous way to go wrong: if the calls never reach a base case, the method calls itself forever. New plates pile onto the call stack with nothing ever coming off, until the stack runs out of room and Java crashes with a StackOverflowError. This is the recursive cousin of the infinite loop.

public class Main {

    // BROKEN: no base case, and n never moves toward one
    static void forever(int n) {
        System.out.println(n);
        forever(n + 1);          // n grows away from any stopping point — never ends!
    }

    public static void main(String[] args) {
        forever(1);              // crashes with StackOverflowError
    }
}
⚠️ Two ways to forget to stop

Infinite recursion happens if you (1) forget the base case entirely, or (2) write a base case but the recursive call moves away from it instead of toward it — like calling forever(n + 1) when the base case is n == 0. Always ask: "Does every call get me closer to stopping?" Go ahead and run the code above to see the crash for yourself — then fix it by adding a base case like if (n > 5) return;.

Exercise — 15 Minutes
⌨️ Coding Challenge ⏱ ~15 min

Task 1 — countUp()
Write static void countUp(int n) that prints the numbers from 1 up to n using recursion (not a loop). countUp(5) should print 1, 2, 3, 4, 5 each on its own line. Hint: to print in increasing order, make the recursive call before you print.

Base case: if (n == 0) return; (nothing to print). Then recurse first, print second: countUp(n - 1); followed by System.out.println(n);. Because the smaller numbers print on the way back up, they come out in order.

Task 2 — sumDigits()
Write static int sumDigits(int n) that adds up the digits of a number using recursion. sumDigits(123) → 6 (because 1+2+3), and sumDigits(4050) → 9.

The last digit is n % 10; the rest of the number is n / 10 (integer division drops the last digit). Base case: if (n == 0) return 0;. Recursive case: return (n % 10) + sumDigits(n / 10);. Each call peels off one digit.

Task 3 — Fix the base case
This method is supposed to return n * 2 but it crashes with a StackOverflowError. Find the bug and fix it so doubleIt(0) → 0 and doubleIt(4) → 8.

public class Main {

    static int doubleIt(int n) {
        // BUG: this base case is never reached. Fix it!
        if (n == 100) {
            return 0;
        }
        return 2 + doubleIt(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(doubleIt(4));
    }
}

The recursive call subtracts 1 (n - 1), so n is always shrinking — it heads toward 0, never toward 100, so the base case never fires. Change the base case to if (n == 0) return 0;. Now doubleIt(4) adds 2 four times → 8.
