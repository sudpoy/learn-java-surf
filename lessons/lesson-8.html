Inheritance

You just learned to build classes. But what if two classes are almost the same? A Dog and a Cat are both Animals — they share a lot. Inheritance lets one class build on another, getting all its fields and methods for free, then adding or changing just the bits that are different. It's how Java avoids copy-paste and models real "is-a" relationships.

Lecture: ~40 min
Exercise: ~15 min
Topics: extends · superclass · subclass · super() · @Override · polymorphism · Object
Part 1 — What Inheritance Is & Why It Helps

Think about how traits pass down in a family. You might inherit your grandmother's eye color and your dad's laugh — you get those "for free," and then you add things that are uniquely you. Classes can work the same way. A general class holds what everything shares, and a more specific class inherits all of it, then adds its own twist.

The test for whether inheritance fits is the "is-a" relationship: a Dog is an Animal, a Car is a Vehicle. When that sentence sounds true, inheritance is usually a good fit. The big win is reuse — write the shared code once in the general class, and every specific class gets it automatically. No copy-paste.

Part 2 — extends: Inheriting Fields & Methods

The keyword extends makes one class a child of another. The child automatically gets all the parent's fields and methods — without writing them again. Here Dog extends Animal, so even though Dog looks almost empty, it already has a name and can eat():

class Animal {
    String name;

    void eat() {
        System.out.println(name + " is eating.");
    }
}

class Dog extends Animal {        // Dog IS-A Animal
    // no fields or methods written here yet...
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.name = "Rex";           // 'name' was inherited from Animal
        d.eat();                  // 'eat()' was inherited from Animal
    }
}
💡 The child gets it all for free

Dog never declares name or eat(), yet both work — because it extends Animal. That's the whole point: shared things live in the parent, and every child inherits them. Write once, reuse everywhere.

Part 3 — Adding New Things in the Subclass

A subclass isn't limited to what it inherits — it can add its own fields and methods on top. The result is "everything the parent has, plus the child's extras." Our Dog keeps the inherited name and eat(), and adds a bark() that only dogs have:

class Animal {
    String name;

    void eat() {
        System.out.println(name + " is eating.");
    }
}

class Dog extends Animal {
    void bark() {                      // brand-new, only on Dog
        System.out.println(name + " says: Woof!");   // can still use inherited 'name'
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.name = "Rex";
        d.eat();      // inherited from Animal
        d.bark();     // added by Dog
    }
}
⚠️ It only goes one way

The child can use everything from the parent, but not the reverse. An Animal variable doesn't have bark() — only Dog added that. Inheritance flows downward: children get the parent's stuff, parents don't get the children's.

Part 4 — super(): Building on the Parent's Constructor

When a parent has a constructor that sets up its fields, the child should reuse it instead of repeating the work. super(...) calls the parent's constructor, and it must be the first line of the child's constructor. Here Animal sets up name; Dog calls super(name) to handle that, then sets up its own breed:

class Animal {
    String name;

    Animal(String name) {
        this.name = name;
    }
}

class Dog extends Animal {
    String breed;

    Dog(String name, String breed) {
        super(name);          // let Animal set up 'name' first
        this.breed = breed;   // then set up Dog's own field
    }

    void describe() {
        System.out.println(name + " is a " + breed + ".");
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog("Rex", "Labrador");
        d.describe();
    }
}
💡 super = "the parent part of me"

Just like this means "this object," super means "the parent's version." super(name) runs Animal's constructor; later you'll also see super.someMethod() to call the parent's version of a method. It lets the child build on top of the parent rather than redoing its work.

Part 5 — Overriding: Changing an Inherited Method

Sometimes the child needs a method to behave differently than the parent's version. Overriding means the child re-writes an inherited method, keeping the same name and parameters but giving it a new body. We mark it with @Override so Java (and other readers) know it's intentional. A generic Animal makes a generic sound; a Cat overrides it:

class Animal {
    String name;

    Animal(String name) { this.name = name; }

    void makeSound() {
        System.out.println(name + " makes a sound.");
    }
}

class Cat extends Animal {
    Cat(String name) { super(name); }

    @Override
    void makeSound() {                                 // same name, NEW behavior
        System.out.println(name + " says: Meow!");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal generic = new Animal("Thing");
        Cat felix = new Cat("Felix");
        generic.makeSound();    // Animal's version
        felix.makeSound();      // Cat's overriding version
    }
}
⚠️ Overriding vs. overloading — don't mix them up

Overriding (this section): a child replaces a parent's method using the same name and parameters. Overloading (Lesson 5): same class, same name but different parameters. Override = same signature, different class. Overload = same name, different signature. The @Override tag only applies to overriding.

Reusing the Parent's Version with super.method()

An override can still call the original parent version using super.method() — handy when you want to add to the parent's behavior instead of fully replacing it:

class Animal {
    void greet() {
        System.out.println("I am an animal.");
    }
}

class Dog extends Animal {
    @Override
    void greet() {
        super.greet();                       // do the parent's part first
        System.out.println("...and I am a dog!");   // then add my own
    }
}

public class Main {
    public static void main(String[] args) {
        new Dog().greet();
    }
}
Part 6 — A Gentle Intro to Polymorphism

Here's the magic that overriding unlocks. Because a Dog is an Animal, an Animal variable is allowed to hold a Dog object. And when you call an overridden method, Java picks the version based on the real object, not the variable's type. This is polymorphism — "many forms": one Animal variable, different behavior depending on what it actually holds.

class Animal {
    String name;
    Animal(String name) { this.name = name; }
    void makeSound() { System.out.println(name + " makes a sound."); }
}

class Dog extends Animal {
    Dog(String name) { super(name); }
    @Override void makeSound() { System.out.println(name + " says: Woof!"); }
}

class Cat extends Animal {
    Cat(String name) { super(name); }
    @Override void makeSound() { System.out.println(name + " says: Meow!"); }
}

public class Main {
    public static void main(String[] args) {
        // An array of Animal can hold Dogs AND Cats
        Animal[] zoo = { new Dog("Rex"), new Cat("Felix"), new Animal("Blob") };

        for (Animal a : zoo) {
            a.makeSound();    // each picks ITS OWN overridden version
        }
    }
}
💡 Why this is powerful

The loop doesn't care whether each item is a Dog, a Cat, or a plain Animal — it just calls makeSound() and the right version runs automatically. You could add a Cow class tomorrow and the loop would handle it with zero changes. That's how big programs stay flexible: write code against the general type, let each object behave as itself.

Part 7 — Everything Extends Object

Here's a secret about Java: every class secretly extends a built-in class called Object, even when you don't write extends anything. That's why every object already has a few methods — like toString(), which turns an object into text. By default it prints something ugly, but you can override it (just like Part 5!) to make your object describe itself nicely:

class Dog {
    String name;
    int age;
    Dog(String name, int age) { this.name = name; this.age = age; }

    @Override
    public String toString() {                 // override Object's version
        return "Dog(" + name + ", age " + age + ")";
    }
}

public class Main {
    public static void main(String[] args) {
        Dog d = new Dog("Rex", 3);
        System.out.println(d);        // println calls toString() for you
    }
}
⚠️ You've been using Object all along

Because Dog automatically extends Object, it already had a toString() before you wrote one — it just printed a messy code like Dog@1b6d3586. Overriding toString() replaces that with your own readable text. Every class you've ever written sits at the bottom of one giant family tree with Object at the very top.

Exercise — 15 Minutes
⌨️ Coding Challenge ⏱ ~15 min

Task 1 — Vehicle → Car
Write a Vehicle class with a method void start() that prints "Starting engine...". Then write class Car extends Vehicle that adds a method void honk() printing "Beep beep!". In main, build a Car and call both start() and honk().

Hint: start() is inherited, so a Car can call it even though you only wrote it in Vehicle.

class Vehicle { void start(){ System.out.println("Starting engine..."); } } then class Car extends Vehicle { void honk(){ System.out.println("Beep beep!"); } }. In main: Car c = new Car(); c.start(); c.honk();

Task 2 — Override makeSound()
Write class Animal with void makeSound() that prints "Some sound". Make class Cow extends Animal that @Overrides makeSound() to print "Moo!". Build a Cow, call makeSound(), and confirm you get Moo!.

In Cow, copy the method's signature exactly and add the tag above it: @Override void makeSound(){ System.out.println("Moo!"); }. Same name, same (empty) parameter list — that's what makes it an override rather than a new method.

Task 3 — Polymorphism in a loop
Using your Animal and Cow from Task 2, also make a Duck that prints "Quack!". Put one Cow and one Duck into an Animal[] array, loop over it, and call makeSound() on each. You should see Moo! then Quack!.

Build the array with both child types: Animal[] farm = { new Cow(), new Duck() };. Then for (Animal a : farm) { a.makeSound(); }. Even though the variable type is Animal, each object runs its own overridden version — that's polymorphism.
