Collections

The grand finale! Arrays were great, but they have one big limit: their size is locked in forever. Collections are smarter containers that grow and shrink as you need them. You'll meet the two you'll use most — the ArrayList (a stretchy list) and the HashMap (a labeled lookup) — and pull together everything you've learned across the whole course.

Part 1 — Why Arrays Aren't Enough

Remember arrays from Lesson 4? They're like an egg carton: a fixed number of slots, decided the moment you build it. A 6-slot carton always holds exactly 6 eggs — you can't suddenly fit a 7th. In real programs you often don't know how many things you'll have: a to-do list, players who join a game, messages in a chat. They grow and shrink.

That's what collections are for. An ArrayList is like a shopping bag instead of an egg carton — start empty, drop items in as you go, take some out, and it stretches to fit. No fixed size to worry about.

ArrayArrayList

Add an itemCan't — size is lockedlist.add(x)

Part 2 — Creating an ArrayList

ArrayList isn't built into the language the way arrays are — it lives in Java's toolbox, so you import it at the top of your file. Then you create one, telling it what type of thing it will hold using angle brackets < > — this is called generics. An ArrayList<String> is "a stretchy list of Strings."

import java.util.ArrayList;     // bring ArrayList in from Java's toolbox

public class Main {
    public static void main(String[] args) {
        // an empty, stretchy list that will hold Strings
        ArrayList<String> pets = new ArrayList<String>();

        pets.add("dog");        // drop items in — the list grows
        pets.add("cat");
        pets.add("hamster");

        System.out.println(pets);              // [dog, cat, hamster]
        System.out.println("Size: " + pets.size());   // 3
    }
}
💡 The <String> keeps your list honest

The type in angle brackets means the list only accepts that type — an ArrayList<String> holds Strings and nothing else. Try to add a number and Java stops you before the program even runs. It also means get() hands you back a String directly, no guessing. Printing a list shows its contents in square brackets, just like an array.

Part 3 — The Core ArrayList Methods

An ArrayList comes with a tidy set of methods for everyday work. Like arrays, positions are 0-based — the first item is at index 0:

MethodWhat it does
add(x)Append x to the end (list grows)
get(i)Read the item at index i
set(i, x)Replace the item at index i with x
remove(i)Delete the item at index i (list shrinks)
size()How many items right now
contains(x)Is x in the list? (true/false)
import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<String> todo = new ArrayList<String>();
        todo.add("brush teeth");
        todo.add("walk dog");
        todo.add("homwork");          // oops, typo

        todo.set(2, "homework");      // fix index 2
        System.out.println("Get index 1: " + todo.get(1));   // walk dog
        System.out.println("Has 'walk dog'? " + todo.contains("walk dog"));

        todo.remove(0);               // done brushing — remove it
        System.out.println(todo);                 // [walk dog, homework]
        System.out.println("Left: " + todo.size());   // 2
    }
}
⚠️ remove shifts everything after it

When you remove(0), every later item slides down one spot to fill the gap — what was at index 1 becomes index 0. So be careful removing items while looping forward by index, or you can skip elements. (A for-each loop avoids this when you're only reading.)

Part 4 — Looping Over a List

You loop over an ArrayList just like an array. The for-each loop is cleanest when you just want each item; the indexed loop is handy when you also need the position number:

import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<String> players = new ArrayList<String>();
        players.add("Mia");
        players.add("Leo");
        players.add("Ava");

        // for-each: "for each name in players"
        for (String name : players) {
            System.out.println("Player: " + name);
        }

        System.out.println("---");

        // indexed: when you want the position too
        for (int i = 0; i < players.size(); i++) {
            System.out.println((i + 1) + ". " + players.get(i));
        }
    }
}
💡 size(), not length

The classic mix-up: arrays use arr.length (a field, no parentheses), but an ArrayList uses list.size() (a method, with parentheses). And to read an item it's list.get(i), not list[i]. Different containers, slightly different controls.

Part 5 — Lists of Numbers: Wrapper Types

Here's a small quirk. Collections only hold objects, but int, double, and boolean are not objects — they're simple "primitive" types (Lesson 1). So for a list of whole numbers you use the object version of int, called Integer, in the angle brackets. The good news: Java converts back and forth for you automatically, so you mostly just write plain numbers.

import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<Integer> scores = new ArrayList<Integer>();  // Integer, not int
        scores.add(90);     // you write 90; Java wraps it as an Integer for you
        scores.add(75);
        scores.add(88);

        int total = 0;
        for (int s : scores) {       // and unwraps it back to int here
            total += s;
        }
        double avg = (double) total / scores.size();
        System.out.println("Total: " + total + ", Average: " + avg);
    }
}
⚠️ Use the wrapper names in < >

Inside the angle brackets you need the object names: Integer (not int), Double (not double), Boolean (not boolean). String already is an object, so it stays as-is. This automatic wrapping/unwrapping is called autoboxing — a fancy word for "Java handles the conversion so you don't have to."

Part 6 — HashMap: Looking Things Up by Name

An ArrayList finds things by number (index 0, 1, 2...). But sometimes you want to look something up by a name instead — like a real dictionary, where you look up a word to get its definition. That's a HashMap: it stores key → value pairs. Give it a key, it hands back the matching value, instantly.

import java.util.HashMap;

public class Main {
    public static void main(String[] args) {
        // keys are Strings (names), values are Integers (ages)
        HashMap<String, Integer> ages = new HashMap<String, Integer>();

        ages.put("Mia", 12);        // put a key -> value pair in
        ages.put("Leo", 13);
        ages.put("Ava", 11);

        System.out.println("Leo is " + ages.get("Leo"));        // look up by key -> 13
        System.out.println("Has Mia? " + ages.containsKey("Mia"));   // true
        System.out.println("Has Sam? " + ages.containsKey("Sam"));   // false
    }
}
💡 Two types in the brackets

A HashMap needs two types: HashMap<String, Integer> means "keys are Strings, values are Integers." put(key, value) adds a pair, and get(key) fetches the value for that key. Each key is unique — put with a key that already exists just updates its value.

Looping Over a HashMap

To visit every pair, loop over the keys with keySet(), then use each key to get() its value:

import java.util.HashMap;

public class Main {
    public static void main(String[] args) {
        HashMap<String, Integer> ages = new HashMap<String, Integer>();
        ages.put("Mia", 12);
        ages.put("Leo", 13);

        for (String name : ages.keySet()) {       // for each key...
            System.out.println(name + " is " + ages.get(name));   // ...get its value
        }
    }
}
Part 7 — Which One Should I Use?

You now know three containers. Picking the right one is a real skill — here's the quick guide:

Use thisWhen you…Example
ArrayKnow the exact size up front and it won't changeThe 7 days of the week
ArrayListHave an ordered list that grows/shrinksA to-do list, players in a game
HashMapLook things up by a name/key, not a positionUsername → score, word → definition

A good question to ask yourself: "How will I find my data again?" If by position number, a list. If by a label, a map. If you'll never resize it, a plain array is fine.
