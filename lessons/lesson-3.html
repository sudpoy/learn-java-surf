Loops

Part 1 — The while Loop

Imagine telling a friend "keep bouncing the ball while it stays on the table." They check the condition, do the action, and check again — over and over — until the condition is no longer true. That's exactly what a while loop does: it repeats a block of code as long as its condition stays true.

Basic Structure

Java checks the condition first. If it's true, the body runs; then it checks again. The moment the condition becomes false, the loop stops and the program continues below it. Something inside the loop must eventually make the condition false — otherwise it never ends.

int count = 5;

while (count > 0) {
    System.out.println(count);
    count--;            // this is what eventually ends the loop
}

System.out.println("Liftoff!");
💡 Read it out loud

"While count is greater than 0, print it and subtract 1." Each trip through the loop is called an iteration. This loop iterates 5 times (count = 5, 4, 3, 2, 1), then stops when count hits 0.

⚠️ The forgotten update = infinite loop

If you remove count--, count stays 5 forever, count > 0 is always true, and the loop never stops. We'll come back to these "infinite loops" at the end — they're the #1 loop bug.

Part 2 — The do-while Loop

A do-while loop is a while loop's twin with one key difference: it runs the body first, then checks the condition. This guarantees the body runs at least once, even if the condition was false from the start. Think of a menu that always shows once before asking "do you want to go again?"

Runs At Least Once

Notice the condition below is false immediately — yet the body still runs one time, because the check happens at the bottom:

int number = 10;

do {
    System.out.println("Number is " + number);
    number--;
} while (number > 12);   // false right away — but the body already ran

System.out.println("See? The body ran once anyway.");
💡 while vs do-while — which do I pick?

Use while when the body might need to run zero times (check first). Use do-while when it should always run at least once (act first, then decide whether to repeat) — like asking a player for a move before checking if the game is over.

Part 3 — The for Loop

When you know how many times you want to repeat something — or you're counting through a range — the for loop is the cleanest choice. It packs three things onto one line: where to start, when to stop, and how to step each time.

The Three Parts

PartExampleWhat it does
Initializationint i = 1Runs once at the very start — sets up the counter
Conditioni <= 5Checked before every iteration — loop runs while it's true
Updatei++Runs after every iteration — moves the counter along
for (int i = 1; i <= 5; i++) {
    System.out.println("i is " + i);
}

Counting in Different Ways

The three parts are flexible. You can count down, or step by more than one. Here we count down from 10 to 0, two at a time:

for (int i = 10; i >= 0; i -= 2) {
    System.out.print(i + " ");
}
System.out.println();   // finish with a clean new line
💡 for and while are interchangeable

Any for loop can be rewritten as a while loop and vice-versa. for just keeps the start, stop, and step neatly in one place, so it's harder to forget the update. Use for for counting; use while when you don't know the number of repeats in advance.

Part 4 — The Enhanced for-each Loop

Often you don't care about a counter at all — you just want to visit every item in a list. The for-each loop does exactly that: it hands you one element at a time, with no index to manage and no chance of going out of bounds. (You'll learn all about arrays next lesson — for now, just know { } makes a list of values.)

Visiting Every Item

Read the : as the word "in" — "for each score in scores":

int[] scores = {85, 92, 78, 99, 60};

int total = 0;
for (int score : scores) {
    System.out.println("Score: " + score);
    total += score;
}
System.out.println("Total: " + total);
⚠️ for-each has no index

The for-each loop is perfect for reading every item, but it doesn't give you a position number, and you can't easily change the items inside it. When you need the index (or want to modify elements), use a classic for loop with scores[i].

Part 5 — break and continue

Sometimes you need to steer a loop mid-flight. Two keywords let you do that: break jumps out of the loop entirely, and continue skips the rest of the current turn and jumps straight to the next one.

break — stop early

Once you've found what you're looking for, why keep searching? break ends the loop immediately:

int[] numbers = {4, 8, 15, 16, 23, 42};

for (int n : numbers) {
    if (n == 16) {
        System.out.println("Found 16! Stopping the search.");
        break;          // leave the loop right now
    }
    System.out.println("Checking " + n + "... not it");
}

continue — skip this one

continue doesn't end the loop — it just abandons the current iteration and moves on. Here we skip the even numbers and only print the odd ones:

for (int i = 1; i <= 10; i++) {
    if (i % 2 == 0) {
        continue;       // even number — skip the print below
    }
    System.out.println(i + " is odd");
}
💡 break leaves, continue skips

Easy way to remember: break = "I'm done, get me out of here." continue = "skip the rest of this lap, start the next one." In nested loops, both only affect the innermost loop they sit in.

Part 6 — Nested Loops

You can put a loop inside another loop. The outer loop is like the rows of a grid, and the inner loop fills in the columns of each row. For every single turn of the outer loop, the inner loop runs all the way through.

A Multiplication Grid

The outer loop picks a row (1, 2, 3); the inner loop walks across the columns and prints row × col. The \t is a tab, lining the numbers up into a neat grid:

for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 3; col++) {
        System.out.print(row * col + "\t");
    }
    System.out.println();   // new line after each row finishes
}
⚠️ Nested loops multiply the work

A 3×3 nest runs the inner body 9 times. A 100×100 nest runs it 10,000 times. Nesting is powerful for grids and tables, but the work grows fast — keep an eye on how big your numbers get.

Part 7 — Infinite Loops & Off-by-One

Two mistakes trip up every new programmer. Knowing them now saves you hours of head-scratching later.

Off-by-One: the boundary trap

List positions (indexes) start at 0, so a list of 3 items has indexes 0, 1, and 2 — there is no index 3. Using < with length visits exactly the valid positions. Using <= would step one too far and crash:

int[] letters = {10, 20, 30};

// CORRECT: i < length stops at the last valid index (2)
for (int i = 0; i < letters.length; i++) {
    System.out.println("Index " + i + " = " + letters[i]);
}

// Using  i <= letters.length  would try letters[3], which does not
// exist, and crash with ArrayIndexOutOfBoundsException.
⚠️ Infinite loops — when the loop never ends

An infinite loop happens when the condition can never become false. The usual cause is forgetting to update the counter (i++), or updating it the wrong way (i-- when you meant i++). Always ask: "what makes this loop eventually stop?" Try the demo below and set the step to 0 to see one.

Exercise — 15 Minutes
⌨️ Coding Challenge ⏱ ~15 min

Task 1 — Sum 1 to 100
Use a loop to add up every whole number from 1 to 100 and print the total. Then change it to sum only the even numbers. The full total should come out to 5050.

Hint: keep a running total in a variable that starts at 0, and add the loop counter to it each time.

Start with int total = 0; then loop for (int i = 1; i <= 100; i++) total += i;. For evens only, add an if (i % 2 == 0) inside, or step by 2 with i += 2 starting from 2.

Task 2 — Times Table
Ask for (or pick) a number, then use a for loop to print its times table from 1 to 12 — like 7 x 1 = 7, 7 x 2 = 14, and so on.

Loop i from 1 to 12 and print n + " x " + i + " = " + (n * i). Wrap the multiplication in parentheses so Java does the maths before joining the text.

Task 3 — Find the Largest
Given int[] nums = {3, 7, 2, 9, 4};, use a loop to find and print the biggest number (it's 9) — without sorting. Try it once with a for-each loop.

Keep a variable max starting at the first value (or a very small number). For each item, if it's bigger than max, update max. After the loop, max holds the largest.
